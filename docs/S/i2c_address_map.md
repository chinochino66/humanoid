## 3. PCA9685のAll Callアドレス重複について

PCA9685は、個別アドレス（0x40／0x41）に加えて、**工場出荷時デフォルトで All Call アドレス 0x70 にも応答する。**MODE1レジスタ（0x00番地）のALLCALLビット（bit0）が出荷時 `1`（有効）のため、**本システムのPCA9685 #1・#2は両方とも0x70に同時応答する状態にある。**

### (a) 両基板同時応答の可否

0x70宛のI²C書き込みは、**PCA9685 #1・#2の両方に同時に作用する。**これは以下の場合に危険となり得る：

- ソフトウェアのバグや配線ミスで意図せず0x70へ書き込んだ場合、L系（目・瞼・首・顎）とR系予約・S系（喉ゲート等）の両基板のサーボが**同時に**動く
- E-STOP復帰時など、特定の基板のみへ中立値を書き込むつもりが、0x70経由で両基板に書き込まれる

一方、起動シーケンス（`docs/S/power_tree.md` §8）の「全chに中立値を書き込む」ステップのように、**両基板に同一内容を一括で書き込みたい場面では有用**な面もある。ただし、この起動シーケンスでは元々OE（出力イネーブル）ピンD4が両基板共通のハードウェア結線であり、出力停止・再開はI²Cを介さずピンレベルで既に両基板同時に制御できている。**All Callが無ければ起動シーケンスが成立しないわけではない。**

**本書の判断**：意図しない同時書き込みのリスクが、起動時一括書き込みの利便性を上回ると判断し、**両基板のAll Callを無効化することを推奨する。**

### (b) 無効化手順

Mega初期化時（OE=HIGHの間、§出力停止状態）に、両基板それぞれのMODE1レジスタのALLCALLビット（bit0）を`0`に書き込む。個別アドレス（0x40／0x41）でMODE1レジスタへアクセスするため、無効化そのものは基板ごとに独立して行える。

**この初期化コードは本書執筆時点で未実装。**`docs/OPEN_ISSUES.md` へ「PCA9685 All Callアドレス2枚重複の扱い」として登録済みの項目に対応する実装タスクとする。

### (c) Sub-callアドレスの扱い

PCA9685はAll Callの他に、Sub1／Sub2／Sub3の3つのグループアドレス（MODE1レジスタのSUB1／SUB2／SUB3ビット、デフォルトアドレスはそれぞれ0x71／0x72／0x74）を持つ。**これらは工場出荷時デフォルトで無効（ビット=0）であり、現状は両基板とも応答しない。**

将来、特定チャンネル群を同期駆動する目的でSub-callを有効化する場合、**両基板が同一のデフォルトアドレスに設定されると、All Callと同じ「両基板同時応答」の問題が再発する。**Sub-callを使う場合は、基板ごとに異なるSUBADRレジスタ値へ変更すること。本書時点では未使用（無効のまま）とし、有効化する際は本書を更新すること。

## 4. 空きアドレス帯

I²Cの7ビットアドレス空間は0x08〜0x77が汎用領域（0x00〜0x07と0x78〜0x7Fは予約用途）。現在使用中のアドレスは以下の通り：

**使用中**：0x29、0x40、0x41、0x44、0x45、0x48、0x49、（0x70はAll Call、§3参照）

**空きアドレス帯**：
- 0x08〜0x28
- 0x2A〜0x3F
- 0x42〜0x43
- 0x46〜0x47
- 0x4A〜0x6F
- 0x71〜0x77（うち0x71／0x72／0x74はPCA9685のSub-callデフォルトのため、Sub-call有効化時は要注意。§3(c)参照）

新規I²Cデバイスを追加する場合、上記の空きアドレス帯から選定し、本書を更新すること。
