## 判断日

2026-08-04

## 誤りの内容

L/R/S/M体系への移行時（2026-08-04、コミット1〜7）、L2 InMoov頭部の目関連軸を「eyeX／eyeY（両目共通2軸）＋eyelidLeft／eyelidRight（瞼2軸）＝計4軸」として `docs/L/channel_map_L2.md`・`docs/L/servo_assignment_L2.md`・`docs/S/power_tree.md` に記載していた。

これは誤りだった。正しくは、InMoov公式のi2Eyes機構は**片目あたり4サーボ（眼球X/Y・上瞼・下瞼）×左右＝計8軸、かつ左右は機械的に連動せずソフトウェア同期**である。

## 発見経緯

「蓮冥頭部 開発手順書 Version 2.0」の部品表が「瞼×4→SG92R」としていたのに対し、リポジトリは瞼2軸（eyelidLeft／eyelidRight）としており、数量の不一致が生じていた。この不一致を一次情報で確認する過程で、`inmoov.fr/eyes-i2/` を直接確認した結果、瞼だけでなく眼球側も含めて軸数の誤認があったことが判明した（旧「eyeX/eyeY共通2軸」自体が誤りであり、正しくは眼球も左右独立4軸）。

**教訓（軸数確認の手順）**：当初は瞼の軸数（2か4か）についてWeb検索・AI要約で確認しようとしたが、`inmoov.fr/eyes-i2/` と `inmoov.fr/headi2/` の記述に見かけ上の矛盾があり（前者は「2 servos drive the eyelids」、後者はMyRobotLabの4チャンネル名を列挙）、一度は「未確認」として `docs/OPEN_ISSUES.md` #30 へ登録した。その後、部品表の見出し（「i2Eyes printed parts for **1 Right Eye**」＝片目分の記載であること）とネジ本数（3×10mmネジ8本＝片目4サーボ分の固定具と一致）まで踏み込んで確認したことで、誤認が解けた。

## 正しい軸数と根拠

出典: `inmoov.fr/eyes-i2/`、取得日 2026-08-04

- 部品表の見出しは「i2Eyes printed parts for 1 Right Eye」＝片目分の記載である
- 片目あたり4サーボ（main baseに2個＝眼球X/Y、side baseに2個＝上瞼・下瞼）
- 3×10mmネジ8本（main base 4本＋side base 4本）が片目4サーボの固定数と一致する
- 両目で計8サーボ。**眼球4軸・瞼4軸**
- 公式指定サーボは **JX PDI-1109MG**（「4 servos JX PDI 1109MG」と明記）
- 公式は「安価なSG90は避けろ、長持ちしない（avoid using cheap SG90, they won't last long）」と明記している
- i2Eyesは**左右独立サーボ**であり、機械的な連動ではなく**MyRobotLab側のソフトウェア同期**で左右を揃える設計である（作者Gael Langevinの記載）

## 再発防止

- **軸数・数量の確認は、部品表の見出しの適用範囲（片目分か両目分か等）まで確認する。**「瞼×4」のような数量記載だけでなく、それが片側分か両側分かを取り違えると、実際の軸数を過小評価する。
- **組立手順のネジ本数・固定具数など、数量が独立に裏付けられる情報と突き合わせる。**本件では「3×10mmネジ8本＝片目4サーボ分」というネジ本数が、サーボ本数の傍証として機能した。数量の食い違いに気づいた際は、Web検索の要約だけで終わらせず、可能な限りこうした独立した裏付けを探すこと。
- **一次情報間で見かけ上の矛盾がある場合、「未確認」で済ませる前に、より詳細な記述（見出し・注記・数量根拠）まで読み込む。**本件では `eyes-i2/` と `headi2/` の記述の粒度の違い（ハードウェア台数 vs ソフトウェアチャンネル名）が矛盾に見えていただけで、実際には矛盾していなかった。
